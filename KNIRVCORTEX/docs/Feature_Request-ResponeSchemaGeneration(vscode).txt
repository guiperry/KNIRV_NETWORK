2. Determine Desired Output Schema (Extension-Side Logic)

This is the core logic we'll write. Before calling the Cerebras API, this function analyzes the tracked metrics and the user's current query to decide on the response structure.

javascript
function determineOutputSchema(userMetrics, userQuestion) {
    let schema = {
        type: "object",
        properties: {
            main_response: { type: "string", description: "The primary answer to the user's query." }
        },
        required: ["main_response"]
    };

    // --- Example Rules ---

    // Rule: If sentiment is low, add empathy
    if (userMetrics.sentimentAvg < -0.1) {
        schema.properties.empathy_statement = {
            type: "string",
            description: "A brief statement acknowledging the user's likely feeling (e.g., frustration)."
        };
        // schema.required.push("empathy_statement"); // Make it required? Optional.
    }

    // Rule: If query relates to a known interest, add related info
    const interests = userMetrics.interests || {};
    const queryLower = userQuestion.toLowerCase();
    const relevantInterests = Object.keys(interests).filter(kw => queryLower.includes(kw));
    if (relevantInterests.length > 0) {
        schema.properties.related_interest_info = {
            type: "string",
            description: `Briefly mention or elaborate on the related topic: ${relevantInterests.join(', ')}.`
        };
    }

    // Rule: If query relates to a tracked goal
    const goals = userMetrics.goals || [];
    const relevantGoal = goals.find(g => queryLower.includes(g.description.substring(0, 20))); // Basic match
    if (relevantGoal) {
        schema.properties.goal_context = {
            type: "object",
            properties: {
                goal_mentioned: { type: "string", description: "The goal being discussed." },
                status_update: { type: "string", description: "A comment on the goal's status or progress." },
                next_step_suggestion: { type: "string", description: "A suggestion for the next step towards the goal." }
            },
            required: ["goal_mentioned"]
        };
    }

    // Rule: If personality suggests concise answers are preferred (example metric)
    if (userMetrics.prefersConcise) { // Assuming we track this
         schema.properties.main_response.description += " Keep this part concise.";
         schema.properties.summary = { type: "string", description: "A one-sentence summary if the main response is long." };
    }


    // Return the schema description (e.g., as a JSON string or object for the prompt)
    // Using JSON.stringify is often easiest for inserting into the prompt.
    return JSON.stringify(schema, null, 2);
}

// Helper to load metrics (call this before determineOutputSchema)
function loadUserMetrics(context) {
    return {
        sentimentAvg: context.workspaceState.get('userSentimentAvg'),
        interests: context.workspaceState.get('userInterests'),
        goals: context.workspaceState.get('userGoals'),
        // Add other tracked metrics
        prefersConcise: context.workspaceState.get('userPrefersConcise')
    };
}

4. Process the Structured Response (Extension-Side Logic)

Parse the JSON and use its contents.

javascript
function processStructuredResponse(responseText, webviewPanel) {
    try {
        // Clean potential markdown fences if the LLM adds them accidentally
        const cleanedText = responseText.replace(/^```json\s*|```\s*$/g, '');
        const structuredData = JSON.parse(cleanedText);

        // Now use the structured data to build a user-friendly display
        let displayHtml = `<p>${structuredData.main_response}</p>`; // Always expect main_response

        if (structuredData.empathy_statement) {
            displayHtml = `<p><em>${structuredData.empathy_statement}</em></p>` + displayHtml;
        }
        if (structuredData.related_interest_info) {
            displayHtml += `<p><small>Related topic: ${structuredData.related_interest_info}</small></p>`;
        }
        if (structuredData.goal_context) {
            displayHtml += `<div><strong>Regarding Goal: ${structuredData.goal_context.goal_mentioned}</strong><br/>`;
            if(structuredData.goal_context.status_update) displayHtml += `Status: ${structuredData.goal_context.status_update}<br/>`;
            if(structuredData.goal_context.next_step_suggestion) displayHtml += `Suggestion: ${structuredData.goal_context.next_step_suggestion}<br/>`;
            displayHtml += `</div>`;
        }
        if (structuredData.summary) {
             displayHtml += `<p><b>Summary:</b> ${structuredData.summary}</p>`;
        }


        // Send the formatted HTML to the webview
        webviewPanel.webview.postMessage({ command: 'addResponse', content: displayHtml });

    } catch (error) {
        console.error('[Cerebras] Failed to parse structured JSON response:', error);
        console.log('[Cerebras] Raw response:', responseText);
        // Fallback: Display the raw response (or an error message)
        webviewPanel.webview.postMessage({
             command: 'addResponse',
             content: `<p>Error processing response. Raw output:</p><pre>${responseText}</pre>`
         });
    }
}
Key Considerations:

LLM Reliability: Getting the LLM to consistently output valid JSON matching a dynamic schema requires careful prompt engineering and a capable model. Test extensively.
Schema Complexity: Keep the dynamically generated schemas relatively simple at first. Overly complex or deeply nested schemas increase the chance of LLM errors.
Error Handling: Robust try...catch blocks around JSON parsing are essential. Decide on a good fallback behavior (show raw text, ask the LLM to retry, show an error message).
Prompt Length: Injecting the schema description into the prompt consumes tokens. Ensure our context length management accounts for this.
Metric Quality: The effectiveness hinges on how well our extension tracks meaningful user metrics. Start simple and refine.

This approach shifts the "schema generation" intelligence into our extension code, using the LLM as a powerful engine to fill the structure we define based on our understanding of the user. It's a complex but potentially very rewarding way to create a more adaptive AI assistant!
