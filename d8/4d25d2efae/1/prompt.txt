    What's working:
    - /dashboard redirects correctly to /gateway (302)
    - The gateway's initial HTML and CSS load via the proxy
    - Gateway chunks served via /gateway/_next/static/... return 200
    
    What's broken:
    - The gateway's SPA navigates to dozens of client-side routes (/bootnode-dao, /network-inference-dao, /chain-explorer, etc.) and the referer-based proxy can't catch all possible paths
    - The gateway's embedded JS has hardcoded API endpoints pointing to http://localhost:3001 (Payment Gateway) and http://localhost:8080 — these services aren't running
    - The gateway expects to be served on its own TCP port with direct access to its API backends
    
    The WebGUI is designed to run as a standalone app served by the knirvgateway binary on its own port, not proxied through another server. The proxy handles the initial load but fails on SPA navigation and hardcoded API calls.
