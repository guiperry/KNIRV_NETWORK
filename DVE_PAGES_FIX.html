1. Target Architecture

The DVE verification pages live as Go HTML templates served by the KNIRVSERVER backend_server (port 8082 / Unix socket), proxied through the KNIRVGATEWAY (port 8080) for public access. The KNIRVSERVER frontend's DVE workspace panel loads them in an iframe pointed at the gateway URL.

4. Phase 2 — Gateway Proxy Route for /dve/*

2 Critical ~1 hr · 2 files

Add a reverse-proxy route on the KNIRVGATEWAY so /dve/{dveId}* requests proxy through to the backend server's Unix socket — following the exact same pattern as /api/v1/, /api/oracle/, etc.

Rationale

The gateway is the public entry point. The backend server listens on an internal Unix socket. The newSocketProxy() function already exists. DVE routes need the same treatment.

Step 2.1 — Add /dve/ proxy route

packages/KNIRVGATEWAY/internal/server/server.go

In setupRoutes(), after the Backend proxy registration (~line 289), add:

// DVE public pages proxy — serve per-DVE verification HTML pages // from the backend_server's DVEProxyHandler via Unix socket. // Routes: /dve/{dveId}, /dve/{dveId}/validation, /dve/{dveId}/metrics, // /dve/{dveId}/search, /dve/{dveId}/validate if s.config.BackendSocketPath != "" { dveProxy := newSocketProxy(s.config.BackendSocketPath, "http://knirvserver") r.PathPrefix("/dve/").Handler(dveProxy) s.logger.Info("DVE public page proxy registered", zap.String("socket", s.config.BackendSocketPath)) } else { s.logger.Warn("DVE public page proxy not configured — /dve/* will not be proxied") }

Important ordering: Register /dve/ before the catch-all / WebGUI SPA handler (~line 618), so the DVE routes take priority over the SPA shell.

8. Key Design Decisions Log

DecisionChoiceRationale
Where do DVE HTML pages live? KNIRVSERVER backend_server (Go templates, port 8082 / Unix socket) Already implemented, closest to validation data, no N+1 network hops. Templates render server-side for fast initial load.
