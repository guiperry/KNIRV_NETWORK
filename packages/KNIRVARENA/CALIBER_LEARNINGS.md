# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[gotcha]** The active KNIRVARENA source is `packages/KNIRVARENA/src/` (React + Three.js, built with Vite from the package root) — not `packages/KNIRVARENA/packages/ts_client_2/` as the root CLAUDE.md component map suggests. Verify which tree you're in before editing.
- **[pattern]** KNIRVARENA is served under the `/arena/` URL prefix through the gateway's Unix-socket reverse proxy. Three places must stay in sync: `vite.config.ts` `base: '/arena/'`, `App.tsx` `<Router basename="/arena">`, and the proxy mounts in KNIRVGATEWAY `internal/server/server.go` / KNIRVSERVER `main.go`. Changing one without the others breaks asset loading or client-side routing.
- **[gotcha]** When mounting an SPA behind a path-prefix proxy in this repo, the exact prefix path (e.g. `/arena`) must redirect to the trailing-slash form (`/arena/`) — otherwise the file server looks for a non-existent directory entry and returns 404. Both KNIRVGATEWAY and KNIRVSERVER needed this redirect.
- **[pattern]** To deploy a new KNIRVARENA build into the embedded server: run `npm run build:frontend` in `packages/KNIRVARENA`, then `cd dist && tar czf` the contents and copy the archive over `packages/KNIRVSERVER/pkg/knirvarena/bin/knirvarena.tar.gz`. KNIRVSERVER serves the arena from this embedded tarball, not from the dist directory — rebuilding alone does nothing until the tarball is replaced.
- **[env]** The gateway's arena proxy is only registered when `ARENA_SOCKET_PATH` is set (defaults to empty in `internal/config/config.go`); without it `/arena/*` silently isn't proxied and the server logs only a warning.
- **[pattern]** In `packages/KNIRVARENA`, `npm run build` runs `tsc --noEmit` before `vite build`, while `npm run build:frontend` is Vite-only with no type check. Use `build` (or a separate `tsc --noEmit`) to catch type errors; `build:frontend` will happily bundle code that doesn't type-check.
- **[convention]** Upstream services behind the gateway's `newSocketProxy` must not set their own CORS, `X-Frame-Options`, or CSP headers — the proxy strips them so the gateway middleware is the single authority. Add such headers at the gateway, not in backend services.
- **[gotcha]** In `packages/KNIRVARENA`, all tool configs live in the `config/` subdirectory (`jest.config.cjs`, `eslint.config.js`, `babel.config.cjs`), not the package root. Because of this, Jest's `<rootDir>` resolves to `config/` and the `setupFiles` entries (`tests/polyfills.ts`, `jest.setup.js`) fail to resolve — `npx jest --config config/jest.config.cjs` errors out, and adding `--rootDir .` just fails on a different setup file. This is pre-existing breakage in `npm test`; verify changes with `npx tsc --noEmit` instead of trying to run the unit tests.
- **[pattern]** When wiring KNIRVARENA UI features into game state, the zustand store at `src/components/game/stores/useKnirvana.tsx` is the single source of truth — exported helpers (`isRingSet`, `isRingCommitted`, `ringCount`, `RING_SIZE`) already exist for ring/anchor state; use them instead of re-deriving anchor geometry math (radius/angle position matching) in components.
