# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[context]** packages/KNIRVBASE/go/ is the source-of-truth implementation for KNIRVBASE; Rust and TS must conform to it. When discrepancies exist between language implementations, Go's behavior is authoritative
- **[gotcha]** `packages/KNIRVSHELL/go.mod` declares module `github.com/KNIRV/KNIRV_NETWORK/KNIRVCLI`, but the spec and `internal/` imports reference `github.com/knirv/knirvshell`. The package is uncompilable until one name is chosen and applied consistently across all files.
- **[gotcha]** `packages/KNIRVSHELL/go.mod` previously had duplicate `require` entries for OpenTelemetry packages and `golang.org/x/sys` with conflicting versions. Always run `go mod tidy` inside `packages/KNIRVSHELL/` after any dependency change — do not trust the lockfile as-is.
- **[gotcha]** In `packages/KNIRVBASE/go/pkg/nrv/bracket.go`, `SyntacticProfile.DepHead` must be `int8` (not `int16`) to match the `Bracket.DepHead` field and the single-byte wire slot at offset 0x27. Using `int16` causes type mismatches in encode/decode paths.
- **[gotcha]** `nrv.EncodeBracket` must encode the Reserved field (`copy(buf[65:80], b.Reserved[:])`), and `DecodeBracket` must decode it back (`copy(b.Reserved[:], buf[65:80])`). Omitting Reserved encoding causes silent data loss in round-trips — round-trip tests comparing `decoded.Reserved != b.Reserved` will catch this but the bug is non-obvious.
- **[pattern]** The KNIRVBASE Go module path is `github.com/knirvcorp/knirvbase/go` — not `github.com/KNIRV/KNIRV_NETWORK/packages/KNIRVBASE/go`. Use this path when adding import aliases or cross-package references within `packages/KNIRVBASE/go/`.
- **[gotcha]** When editing `packages/KNIRVBASE/go/internal/query/knirvql.go`, only import `encoding/binary` and `math` if functions that use them are actually present and called in the final file. Go rejects unused imports — missing this causes build failures that look unrelated to the query logic being added.
- **[gotcha]** `go test` in `packages/KNIRVBASE/go/` must be run from within that directory with relative package paths (e.g. `./pkg/nrv/...`). Running from the repo root gives "cannot find main module" because each KNIRV package has its own `go.mod`.
- **[correction]** `LSHSalt` does not exist as a separate field in the NRV wire spec — it IS the `GoldenSeed`. Never create or reference a separate `LSHSalt` field in `Bracket`; remove any test assertions on `decoded.LSHSalt` and rename any document index keys from `lsh_salt` to `golden_seed`.
- **[correction]** `GoldenSeed` encodes to exactly ONE wire location: bytes 61–64 (slot 11, offset 0x3D–0x40). Previous code incorrectly wrote it to both 0x2B–0x2E and 0x3D–0x40. The correct 80-byte wire map is: projections (0–31), SubSecondUS (32–35), syntactic packed byte (36), CPU reserved (37–38), DepHead (39), IntentFlags (40), DomainSig (41–42), Memory/context bridge (43–60), GoldenSeed (61–64), Z3/reserved (65–79).
- **[correction]** `Bracket.Memory` is 18 bytes (wire bytes 43–60, slots 6–8), not 14. Using `[14]byte` for Memory misaligns GoldenSeed out of its canonical slot at 61–64 and breaks the wire layout.
- **[correction]** Wire byte 36 (slot 4) is a single packed byte encoding POS (low nibble), tense, and plurality via `PackSyntacticByte`. Earlier incorrect layouts split these across bytes 36/37/38 as three separate fields. Always encode slot 4 as one packed byte and decode with `UnpackSyntacticByte`.
- **[fix]** In `FrameTicker.AppendBracket`, the anchor bracket (`lastIBkt`) must be stored via `cloneBracketShallow(b)`, not as a raw pointer. Storing the raw pointer means subsequent P-frame XOR mutations overwrite the anchor's `Projections` field, silently corrupting drift detection for all future brackets in the same frame.
- **[gotcha]** `packages/KNIRVSERVER/pkg/knirvagent/` is the KNIRVSERVER-side process manager (its own `go.mod`, module `github.com/KNIRV/KNIRV_NETWORK/KNIRVAGENT`). The KNIRVAGENT *binary source* lives at `packages/KNIRVAGENT/` (module `github.com/knirvcorp/knirvagent`). These are two distinct modules — editing one has no effect on the other.
- **[correction]** New library code for the KNIRVAGENT binary must go in `packages/KNIRVAGENT/pkg/<subpackage>/` subdirectories — not at the `cmd/` level and not in `packages/KNIRVSERVER/pkg/knirvagent/`. After changes, rebuild and re-embed: run `go build -o ../KNIRVSERVER/pkg/knirvagent/bin/knirvagent ./cmd/knirvagent/` from inside `packages/KNIRVAGENT/`, then rebuild KNIRVSERVER (which uses `//go:embed bin/knirvagent`).
- **[correction]** All internal inter-service communication uses Unix sockets exclusively; KNIRVGATEWAY (`:8888`) is the sole TCP listener the browser reaches. New KNIRVSERVER `backend/internal/` REST endpoints must be registered under `/api/v1/` (proxied by KNIRVGATEWAY via `backend.sock`); new WebSocket endpoints are registered at the root router (not under `/api/v1/`) and require a separate WebSocket tunnel rule in KNIRVGATEWAY.
- **[gotcha]** `newSocketProxy()` in `packages/KNIRVGATEWAY/internal/server/server.go` uses `httputil.ReverseProxy` which strips `Upgrade` and `Connection` headers — it cannot tunnel WebSocket connections. The gateway currently has no `/ws/*` proxy rule, so all browser WebSocket connections silently fail at the gateway. Fix requires raw TCP hijacking via `http.Hijacker` (not `ReverseProxy`) for any `/ws/` path prefix.
- **[fix]** When `mcp__plugin_socraticode_socraticode__codebase_search` returns empty `{}` for any query in this project, the index is likely stale. Fall back immediately to `find <pkg_dir> -type f -name "*.go" | xargs grep -l <term>` to locate relevant files by content — do not retry codebase_search with rephrased queries.
- **[convention]** KNIRVSERVER REST API routes are versioned under `/api/v1/`. WebSocket routes are registered at the root router outside `/api/v1/` and follow the pattern `/ws/dve/{nodeId}/...`. Do not register WS routes under the versioned prefix.
- **[gotcha]** `packages/KNIRVSERVER/backend/cmd/backend_server/main.go` is too large to read directly with the Read tool (returns empty `{}`). Use targeted grep to extract relevant sections: `grep -n "<pattern>" .../backend/cmd/backend_server/main.go | head -40`.
- **[gotcha]** KNIRVSERVER frontend tests use Jest 30 (`jest: ^30.1.0`), not Vitest. The legacy `hud.test.tsx` file mixed `vi` from `@jest/globals` with Jest — always use native Jest API (`jest.fn()`, `jest.useFakeTimers()`, `jest.clearAllMocks()`) when writing or modifying frontend tests. Do not import `vi` from `@jest/globals`.
- **[fix]** Running `npx jest --testPathPattern=...` in `packages/KNIRVSERVER/frontend/` silently returns empty `{}` (times out with no output). Use `npm run test -- --testPathPattern=<pattern>` or `npm test` to run the full suite.
- **[pattern]** New KNIRVSERVER system-level API endpoints that need access to top-level `ServerApp` fields (e.g., the `Updater`) must be added as early-return `if c.Request.URL.Path == "/api/v1/..."` cases inside `main.go`'s `api.Any("/*path", ...)` catch-all handler, before the proxy-to-backend fallthrough. The backend `APIRouter` cannot reach `ServerApp` state.
- **[gotcha]** The `DVEURIRegistry` (`backend/internal/services/dve_uri_registry.go`) is an in-memory map that starts empty on every boot — DVEs created or tracked via `dveManager.NodeTracker` are NOT automatically registered in it. Any handler that exclusively calls `uriRegistry.GetByDVEID()` will always return 404 for live DVEs. Always add a fallback to `dveManager.GetNode()` when looking up a DVE by ID.
- **[gotcha]** Go's `html/template.ExecuteTemplate(w, "public_page.gohtml", data)` requires a template block named exactly `"public_page.gohtml"` to exist in the parsed template set. If a `.gohtml` file only defines inner sub-blocks (`{{ define "header" }}`, `{{ define "content" }}`, etc.) but no top-level block with that filename, the call silently fails or errors. Always add `{{ define "public_page.gohtml" }}{{ template "header" . }}{{ template "content" . }}{{ end }}` at the top of any template file that is referenced by name in `ExecuteTemplate`.
- **[fix]** Registering a named Gin route (e.g. via `registerGatewayPrefix("/api/agent", "/api/agent")`) for a prefix that overlaps with the existing `/api/*path` catch-all PANICS at startup: `"catch-all wildcard '*path' conflicts with existing path segment 'agent'"`. To route `/api/agent/` traffic to KNIRVGATEWAY without triggering this panic, add an early-return `strings.HasPrefix(c.Request.URL.Path, "/api/agent/")` block INSIDE the existing `api.Any("/*path", ...)` catch-all handler — the same pattern used for `/api/network-monitor/`. Do NOT attempt named route registration alongside the catch-all.
- **[gotcha]** Inner agent REST calls (`/api/v1/dve/{dveId}/inner/*`) are registered by the backend subprocess's `InnerAgentHandlers` and proxy to the per-DVE KNIRVAGENT Unix socket (`agent-{dveId}.sock`). Inner agent WebSocket streams (`/ws/dve/{dveId}/inner/*`) are registered by `DVEInnerAgentWSHandler`. Both are served by the backend subprocess — NOT by KNIRVGATEWAY's `dynamicAgentProxy`. Route `/api/agent/` (not `/api/v1/dve/.../inner/`) traffic to the gateway via the HasPrefix pattern above.
- **[correction]** Inner agent frontend API calls must use `/api/v1/dve/${dveId}/inner/...` (e.g. `/spawn`, `/sessions`, `/tools`, `/install`, `/sessions/{sessionId}/input`). The pattern `/api/agent/${dveId}/api/inner/...` is wrong — it targets a non-existent path structure and silently 404s.
- **[gotcha]** KNIRVGATEWAY's `dynamicAgentProxy` reads per-DVE agent socket paths from `AgentSocketDir` (set via `AGENT_SOCKET_DIR` env var, defaults to empty string). KNIRVSERVER `main.go` does not pass `AGENT_SOCKET_DIR` to the gateway subprocess — if unset at the OS level, `dynamicAgentProxy` cannot locate agent sockets and all `/api/agent/` proxying silently fails.
- **[gotcha]** The outer proxy in `packages/KNIRVSERVER/main.go` uses `http.Client{Timeout: 60s}` and the `http.Server` had `WriteTimeout: 15s` — both kill SSE/streaming connections prematurely. Fix: (1) Omit `WriteTimeout` on the `http.Server` (defaults to 0, disabled). (2) Detect SSE requests by checking `Accept: text/event-stream` header OR `?stream=1` query param, and use a `http.Client` with no `Timeout` for those. (3) For SSE responses, flush each chunk via `http.Flusher` instead of buffering with `io.Copy`.
- **[gotcha]** KNIRVHASHER manager (`knirvhasher.Manager`) only initializes when `cfg.Hasher.Enabled` is `true`. If `enabled: true` is absent from the `hasher:` section in a config YAML, the `/api/v1/hasher/status` and training endpoints return 503 even when the binary is present. All three config files (`development.yaml`, `production.yaml`, `testnet.yaml`) now have `enabled: true` under `hasher:`.
- **[pattern]** KNIRVSERVER fast-relink build sequence: for outer `main.go`-only changes, run `make relink` from `packages/KNIRVSERVER/`. For backend changes: `cd backend && go build ./cmd/backend_server/...`, then `make embedded-build`, then `make relink`. For hasher pipeline changes: `make hasher-build` first, then `make embedded-build`, then `make relink`. All make targets must be run from `packages/KNIRVSERVER/`.
- **[gotcha]** KNIRVHASHER pipeline stages in `packages/KNIRVHASHER/pipeline/` each have their own `go.mod` with shorthand local module names (`data-connector`, `data-miner`, `data-encoder`, `data-trainer`). Each stage must be built and tested from within its own subdirectory — they cannot be imported from or built via the root `packages/KNIRVHASHER/` module.
- **[gotcha]** `packages/KNIRVHASHER/pipeline/2_DATA_ENCODER`'s `AutoDetectInputFile()` searches for its input in `$KNIRV_APP_DATA_DIR/json/` and `~/.local/share/hasher/`, in priority order: `ai_knowledge_base_goat_alpaca.json` → `ai_knowledge_base_alpaca.json` → `ai_knowledge_base.json` → `.arrow` variants. If the data-miner writes output to a different path than expected, the encoder silently falls back to a placeholder that doesn't exist and fails immediately with "input file does not exist".
