- **[gotcha]** Go's `html/template.ExecuteTemplate(w, "public_page.gohtml", data)` (`internal/web/dve_proxy_handlers.go`, backend_server) requires a template block named exactly `"public_page.gohtml"` to exist in the parsed template set (templates are loaded via `ParseFS(tmplFS, "*.gohtml")`, not a CWD-relative glob). If a `.gohtml` file only defines inner sub-blocks (`{{ define "header" }}`, `{{ define "content" }}`, etc.) but no top-level block with that filename, the call silently fails or errors. - **[fix]** Registering a named Gin route (e.g. via `registerGatewayPrefix("/api/agent", "/api/agent")`) for a prefix that overlaps with the existing `/api/*path` catch-all PANICS at startup: `"catch-all wildcard '*path' conflicts with existing path segment 'agent'"`. - **[gotcha]** Inner agent REST calls (`/api/v1/dve/{dveId}/inner/*`) are registered by the backend subprocess's `InnerAgentHandlers` and proxy to the per-DVE KNIRVAGENT Unix socket (`agent-{dveId}.sock`). Inner agent WebSocket streams (`/ws/dve/{dveId}/inner/*`) are registered by `DVEInnerAgentWSHandler`. Both are served by the backend subprocess — NOT by KNIRVGATEWAY's `dynamicAgentProxy`. Route `/api/agent/` (not `/api/v1/dve/.../inner/`) traffic to the gateway via the HasPrefix pattern above.
- **[correction]** Inner agent frontend API calls must use `/api/v1/dve/${dveId}/inner/...` (e.g. `/spawn`, `/sessions`, `/tools`, `/install`, `/sessions/{sessionId}/input`). The pattern `/api/agent/${dveId}/api/inner/...` is wrong — it targets a non-existent path structure and silently 404s.
- **[gotcha]** KNIRVGATEWAY's `dynamicAgentProxy` reads per-DVE agent socket paths from `AgentSocketDir` (set via `AGENT_SOCKET_DIR` env var, defaults to empty string). KNIRVSERVER `main.go` does not pass `AGENT_SOCKET_DIR` to the gateway subprocess — if unset at the OS level, `dynamicAgentProxy` cannot locate agent sockets and all `/api/agent/` proxying silently fails.
- **[gotcha]** The outer proxy in `packages/KNIRVSERVER/main.go` uses `http.Client{Timeout: 60s}` and the `http.Server` had `WriteTimeout: 15s` — both kill SSE/streaming connections prematurely. Fix: (1) Omit `WriteTimeout` on the `http.Server` (defaults to 0, disabled). (2) Detect SSE requests by checking `Accept: text/event-stream` header OR `?stream=1` query param, and use a `http.Client` with no `Timeout` for those. (3) For SSE responses, flush each chunk via `http.Flusher` instead of buffering with `io.Copy`.
- **[gotcha]** KNIRVHASHER manager (`knirvhasher.Manager`) only initializes when `cfg.Hasher.Enabled` is `true`. If `enabled: true` is absent from the `hasher:` section in a config YAML, the `/api/v1/hasher/status` and training endpoints return 503 even when the binary is present. All three config files (`development.yaml`, `production.yaml`, `testnet.yaml`) now have `enabled: true` under `hasher:`.
- **[pattern]** KNIRVSERVER fast-relink build sequence: for outer `main.go`-only changes, run `make relink` from `packages/KNIRVSERVER/`. Backend_server itself is not buildable from this repo — its source is in the separate sibling `KNIRV_CORP` repo; rebuild it there, then re-vendor the resulting binary here before `make relink`. For hasher pipeline changes: `make hasher-build` first, then `make embedded-build`, then `make relink`. All make targets must be run from `packages/KNIRVSERVER/`.
- **[gotcha]** KNIRVHASHER pipeline stages in `packages/KNIRVHASHER/pipeline/` each have their own `go.mod` with shorthand local module names (`data-connector`, `data-mapper`, `data-encoder`, `data-trainer`). Each stage must be built and tested from within its own subdirectory — they cannot be imported from or built via the root `packages/KNIRVHASHER/` module.
- **[gotcha]** `packages/KNIRVHASHER/pipeline/2_DATA_ENCODER`'s `AutoDetectInputFile()` searches for its input in `$KNIRV_APP_DATA_DIR/json/` and `~/.local/share/hasher/`, in priority order: `ai_knowledge_base_goat_alpaca.json` → `ai_knowledge_base_alpaca.json` → `ai_knowledge_base.json` → `.arrow` variants.
