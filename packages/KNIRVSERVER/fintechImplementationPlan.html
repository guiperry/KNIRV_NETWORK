The Core Problem

The fintech plugin was implemented as an internal service, not as a first-class plugin in the existing plugin framework. As a result:

  • There is no way to activate or deactivate it at runtime through the admin UI
  • The config toggle (fintech.enabled) only takes effect at server startup
  • The frontend dashboard is always visible even when the service is off
  • The FinTechValidatorService is never constructed or injected into the server — the handlers file exists but routes are never registered
  • Payment-processing code (Stripe, PayPal) was placed in a validation plugin rather than in KNIRVORACLE where NRN Faucet transactions belong
  • Core platform services (EvidencePack signing, Certificates, NRV Tracing, Fidelity Scoring, Trajectory Capture, Tick Streaming) are locked inside the fintech package and unavailable to other validation consumers

2Architecture Decision: Plugin vs Service

The existing PluginManagementService manages WASM/LoRA/external binary plugins with lifecycle states: uploaded → deployed → running → stopped. The FinTech validator is a built-in Go service, not a WASM module.

Decision: Register FinTech as a "Built-in System Plugin"

Introduce a BuiltinPlugin interface alongside the WASM plugin framework. FinTech registers as a builtin with a fixed ID (fintech-validator). It appears in the plugin list, can be toggled on/off at runtime via the same plugin API, and persists its enabled state in the database — without needing a WASM binary upload.

Plugin Admin UI
→
POST /api/plugins/fintech-validator/toggle
→
PluginManagementService.SetEnabled()
→
FinTechValidatorService.Start/Stop()
→
Routes mount / unmount

This avoids coupling to WASM infrastructure while still using the existing plugin management UX and API surface. The frontend plugin panel needs one new card; no new pages.

KYC / AML / SEC / Basel ontologies · ComplianceEngine (financial action validation) · Regulatory Scenario Vault · Financial-context NRV annotations. Everything else it previously held is promoted to the core validation platform and re-imported as dependencies.

4Phase 1 — Plugin Registration & Lifecycle

🔌

Register FinTech as a Built-in Plugin

Goal: FinTech validator appears in the plugin list and its lifecycle (start/stop) is managed by PluginManagementService

1

Define the BuiltinPlugin interface

Create a new file backend_server/internal/services/pluginmanagement/builtin_plugin.go:

package pluginmanagement

// BuiltinPlugin is implemented by first-party Go services that want
// to appear in the plugin registry and be toggled at runtime.
type BuiltinPlugin interface {
    PluginID()    string
    PluginName()  string
    Category()    string
    Description() string
    Version()     string

    IsEnabled()   bool
    IsRunning()   bool

    Start(ctx context.Context) error
    Stop(ctx context.Context) error
}
2

Add builtin registry to PluginManagementService

In plugin_management_service.go, add a builtins map and a registration method:

// In PluginManagementService struct
builtins map[string]BuiltinPlugin

func (s *PluginManagementService) RegisterBuiltin(p BuiltinPlugin) {
    s.mu.Lock()
    defer s.mu.Unlock()
    s.builtins[p.PluginID()] = p
}

func (s *PluginManagementService) ToggleBuiltin(id string, enable bool) error {
    p, ok := s.builtins[id]
    if !ok {
        return fmt.Errorf("builtin plugin not found: %s", id)
    }
    if enable {
        return p.Start(context.Background())
    }
    return p.Stop(context.Background())
}

5

Update RegisterRoutes to return 503 when disabled

In handlers.go, replace the early-return route registration skip with a middleware that checks runtime state:

func (h *Handlers) requireEnabled(next http.HandlerFunc) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        if !h.service.IsRunning() {
            w.Header().Set("Content-Type", "application/json")
            w.WriteHeader(http.StatusServiceUnavailable)
            json.NewEncoder(w).Encode(map[string]interface{}{
                "error": "fintech-validator plugin is not enabled",
                "plugin_id": "fintech-validator",
            })
            return
        }
        next(w, r)
    }
}

Wrap all protected routes with this middleware. The status endpoint (GET /api/fintech/status) remains open and returns the current enabled state.

Add a RuntimeConfig() method to the service

func (s *FinTechValidatorService) RuntimeConfig() *Config {
    s.mu.RLock()
    defer s.mu.RUnlock()
    cp := *s.Config
    return &cp
}

func (s *FinTechValidatorService) UpdateConfig(patch *ConfigPatch) error {
    s.mu.Lock()
    defer s.mu.Unlock()
    // Apply only non-nil fields from patch
    if patch.EnableAMLChecks != nil { s.Config.EnableAMLChecks = *patch.EnableAMLChecks }
    if patch.EnableKYCCheks != nil  { s.Config.EnableKYCCheks  = *patch.EnableKYCCheks  }
    // ... rest of flags
    return nil
}

ConfigPatch uses pointer booleans so callers can update individual flags without resetting others.

Goal: One API endpoint to enable/disable, one to read current config — consumed by the frontend

1

Add toggle endpoint in backend_server/internal/web/plugin_management_handlers.go

// POST /api/plugins/builtin/{id}/toggle
func (h *PluginManagementHandlers) HandleToggleBuiltin(w http.ResponseWriter, r *http.Request) {
    id := mux.Vars(r)["id"]
    var body struct{ Enable bool `json:"enable"` }
    json.NewDecoder(r.Body).Decode(&body)

    if err := h.pluginMgmt.ToggleBuiltin(id, body.Enable); err != nil {
        http.Error(w, err.Error(), http.StatusBadRequest)
        return
    }
    json.NewEncoder(w).Encode(map[string]interface{}{
        "plugin_id": id,
        "enabled":   body.Enable,
    })
}

1

Create useBuiltinPlugins hook

New file: frontend/src/hooks/use-builtin-plugins.ts

export function useBuiltinPlugins() {
  const [builtins, setBuiltins] = useState<BuiltinPluginInfo[]>([]);

  const fetch = async () => {
    const res = await apiFetch('/api/plugins/builtins');
    setBuiltins(res.builtins);
  };

  const toggle = async (id: string, enable: boolean) => {
    await apiFetch(`/api/plugins/builtin/${id}/toggle`, {
      method: 'POST',
      body: JSON.stringify({ enable }),
    });
    await fetch();
  };

  useEffect(() => { fetch(); }, []);
  return { builtins, toggle, refetch: fetch };
}
